PySpark: When Python Meets Big Data

Class 10 made the Workbench easy to change. Class 11 asks what happens when the data gets bigger and arrives in another shape. The old case system has sent two years of history as a Parquet file, and next quarter’s export will be ten times larger. You will meet Spark in plain words (driver, executors, partitions), read CSV and Parquet with written schemas, see what is lazy and what runs, build one slice that must agree with the Python code you already trust, and prepare a small, capped list for an AI step that comes later and outside Spark. This class needs Java on your computer, so the install steps in section 3 matter. Read this before class, then arrive with your tools ready.

2. The big idea: prepare in Spark, decide in Python

Think of a warehouse and a front desk. The warehouse (Spark) can sort huge piles of boxes in parallel, but it cannot talk to customers. The front desk (your Python code) makes the decisions, one careful step at a time. The Workbench’s rules should give the same answer whichever of them runs them, and a paid AI call belongs at the front desk, with a cap and a cache, never inside the warehouse.

3.2 Install Java 21

Why Java, when the course is Python? Spark’s engine is written in Scala and runs on the Java Virtual Machine (the JVM). pip install pyspark installs the Python side and the Spark libraries, but not Java itself. When your code starts a SparkSession, Python starts a Java process in the background and talks to it. No Java means no Spark. You install it once, and then you work only in Python.

Download Temurin 21 (LTS), a free Java from the Adoptium project, from this page: adoptium.net/temurin/releases (version 21). On that page, use the filters to choose your operating system and chip, set the package type to JDK, and keep version 21 – LTS. Then follow the steps for your system.

  1. Pick the right file. On the Adoptium page set Operating System to Windows, Architecture to x64 (most Windows PCs; choose aarch64 only for an ARM laptop), Package Type to JDK, and download the .msi installer.
  2. Run the installer. Open the .msi. On the Custom Setup screen, switch on Add to PATH and Set JAVA_HOME variable (click the small drive icon next to each and choose Entire feature will be installed on local hard drive). Then click Next and Install, and allow it when Windows asks.
  3. Open a new terminal. Close every PowerShell and VS Code window and open a new one. Old windows do not see the change.
  4. Check it. Run the two commands below.
Windows PowerShell
java -version
echo $env:JAVA_HOME

Expect openjdk version "21.0... from the first command, and a path such as C:\Program Files\Eclipse Adoptium\jdk-21... from the second. If java is not recognised, the PATH box was not ticked: run the installer again and switch it on.

Windows and Spark: one thing we have not tested Spark can start and read files on Windows with Java alone. Writing Parquet files on Windows can stop with an error that mentions HADOOP_HOME, winutils.exe or NativeIO, because Spark expects some Hadoop helper files that Windows does not have. We tested this course on Mac and Linux, not on Windows. If the check in 3.3 or the class demos show such an error, tell your instructor. The safe fallbacks are Windows Subsystem for Linux (WSL 2, with Ubuntu) or Google Colab.
  1. Find your chip. Open Terminal and run uname -m. arm64 means Apple Silicon (M1, M2, M3, M4): download aarch64. x86_64 means Intel: download x64.
  2. Pick the right file. On the Adoptium page set Operating System to macOS, Architecture to your chip, Package Type to JDK, and download the .pkg installer.
  3. Run the installer. Open the .pkg and click through it. It asks for your Mac password. Homebrew is not needed.
  4. Open a new Terminal window. Old windows do not see the change. Then run the checks and the two settings below, one command at a time.
macOS Terminal: check it
java -version
/usr/libexec/java_home -V

Expect openjdk version "21.0... and a line that names Eclipse Adoptium. If you see Unable to locate a Java Runtime, Java is not installed yet: a fresh Mac has a java command that only points you to a download page.

macOS Terminal: save two settings for every new window
echo 'export JAVA_HOME=$(/usr/libexec/java_home -v 21)' >> ~/.zshrc
echo 'export SPARK_LOCAL_IP=127.0.0.1' >> ~/.zshrc
source ~/.zshrc

JAVA_HOME tells Spark which Java to use. SPARK_LOCAL_IP stops Spark from tripping over Mac network or hostname settings.

Linux: install Java 21 with your package manager (on Ubuntu, sudo apt install openjdk-21-jdk) or download the .tar.gz from the Adoptium page, then check java -version.

When you paste commands Paste one command at a time, without the explanation text. In the Mac terminal, a # comment pasted with a command is read as part of the command and breaks it.

5. Spark in plain words

A normal Python program is one process: it reads, it computes, it writes. A Spark program is a plan and some workers. You write the plan in Python. Spark cuts the data into pieces, hands the pieces to workers, and puts the answers together. Four words cover it.

WordIn plain wordsIn the Workbench
DriverThe one process that runs your script. It builds the plan and receives small resultspython -m meridian_workbench.spark.vertical_slice. It prints the counts and writes manifest.json
ExecutorA worker that runs tasks on pieces of the data. On a cluster, other machines. In local mode, threads inside the same Java processThe judge, the window and the Parquet writes run here
PartitionOne piece of a table. One task works on one partition, and the cores decide how many run at onceThe 200,000-row export is read as 2 partitions, and split into 4 in the demo
SparkSessionThe entry point: the front desk for every requestbuild_session() in spark/session.py

Local mode On your computer there is one Spark Java process. The executors are threads inside it, and your Python script is a separate process. The roles are the same as on a cluster, and the machines are not. That is why we can learn all of this on a laptop, and why we never read a laptop timing as a cluster timing.

6. Lazy plans, actions and native expressions

When you write df.filter(...).select(...), nothing is read. Spark only remembers the plan. Work starts when you ask for a result. This is the most useful fact about Spark, and the cause of most surprises, including a model that gets called twice.

Native first A native expression is a column formula built from Spark’s own functions, such as F.upper or F.when. Spark plans it and runs it inside Java. A UDF is your own Python function used as a column, and Spark has to send each row out to a Python process and back. Use native expressions by default, and a UDF only when nothing native can say it.
